# Архитектура GoldNav

```
Metamod (GiveFnptrsToDll / Meta_Attach / хуки ServerActivate, StartFrame)
        │
core/goldnav_module.cpp — слои навмеша, генераторы, агенты (entity, которых ведём)
        │
        ├─ navmesh/nav_generator   заливка графа от точек спавна
        ├─ navmesh/nav_probe       "сможет ли хулл шагнуть отсюда туда"
        ├─ navmesh/nav_grid        узлы/рёбра, многоэтажность, прямая видимость
        ├─ navmesh/nav_path_planner + pathfinder/astar + path_smoother
        ├─ pathfollower/path_follower + ground_mover   ведение и шаг
        └─ metamod/engine_collision_world, entity_follow_bridge   мост к движку
        │
include/goldnav/goldnav_api.h (extern "C") ← goldnav_amxx (натусы) / другие Metamod-плагины
```

**goldnav_core** (всё, кроме `metamod/` и `core/`) не зависит от SDK: геометрию видит
только через `ICollisionWorld` / `IMoveTracer`. Поэтому генератор, планировщик и ходок
тестируются на синтетическом мире из коробок (`tests/fixtures/box_world.h`).

## Хуллы и слои

Движок сталкивает entity с картой одним из четырёх хуллов (по ширине/высоте bbox):
point, 32x32x36, 32x32x72, 64x64x64. Хуллы разной ширины по-разному опираются на края
уступов, поэтому у каждой ширины свой граф («слой»): point, 32x32 (ducking+standing как
биты на узлах и рёбрах), 64x64. Слой 32x32 строится при старте карты, остальные — по
первому запросу.

## Генерация: заливка, а не сканирование

От точек спавна (и любых досеянных позже точек) от каждого узла пробуется шаг в восемь
соседних клеток — той же логикой «вверх на ступеньку, вперёд, вниз на пол», которой
потом ходит entity. Удался шаг — появляется узел (клетка + высота пола) и ребро: `Walk`
или односторонний `Drop` (спрыгивание). Отсюда:

- границы мира не нужны (у world-энтити GoldSource их нет: absmin/absmax = ±1);
- этажи, мосты и тоннели получаются сами: в одной колонке может быть несколько узлов;
- в граф попадает только достижимое.

Работа размазана по кадрам (`goldnav_gen_budget_ms`). Если entity или цель оказались
там, куда заливка не дошла, туда досеивается новая точка и граф дорастает.

## Путь

A* с весами: расстояние + надбавки за близость к стенам/краям, воду, спрыгивания. Цель
недостижима — путь до ближайшего достижимого места. Затем сглаживание: точки
выбрасываются, если между соседями есть прямая по `Walk`-рёбрам сетки, причём срезанный
отрезок не подходит к стенам ближе, чем сырой путь.

## Движение

Entity двигается кинематически: модуль сам ставит `origin` (скольжение вдоль стен,
подъём на ступеньку до `sv_stepsize`, прилипание к полу на спусках, падение с
гравитацией), держит `velocity = 0` и `FL_ONGROUND` — физика движка для неё пассивна
при любом movetype. Скорость через `pev->velocity` не используется: физика движка для
не-игроков (SV_FlyMove) не умеет подниматься на ступеньки.

Следование: точка пути засчитывается по радиусу или когда её проскочили (с учётом
высоты), перед целью — торможение и остановка точно в ней; упёрлись в другую entity —
обход боком; нет продвижения — путь перестраивается, после нескольких неудач — `FAILED`.
